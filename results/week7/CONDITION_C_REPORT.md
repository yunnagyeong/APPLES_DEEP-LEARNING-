## 4. Meaning Score 구현 방식

LinguaMe의 Meaning Score는 원문과 번역문 사이의 의미 보존 정도를 정량적으로 표현하기 위한 보조 지표이다.

### 4.1 Claim 기반 평가

원문과 번역문에서 각각 Claim을 추출한 후, 양방향 NLI를 이용하여 의미적 뒷받침 여부를 확인한다.

- **원문 → 번역문:** 원문의 핵심 정보가 번역문에 보존되었는지 확인
- **번역문 → 원문:** 번역문에 원문이 뒷받침하지 않는 정보가 추가되었는지 확인

최종 Meaning Score는 다음과 같이 계산한다.

**M = 100 × S^0.2 × C^0.4 × T^0.4 × (1 − R)**

각 변수의 의미는 다음과 같다.

| 변수 | 의미 |
|---|---|
| S | 원문과 번역문의 Semantic Similarity |
| C | 원문 Claim 중 번역문에서 Entailment로 판정된 비율 |
| T | 번역문 Claim 중 원문에서 Entailment로 판정된 비율 |
| R | 양방향 Claim 전체에서 Contradiction으로 판정된 비율 |

Semantic Similarity는 전체적인 의미 유사성을 평가하며, C와 T는 정보의 누락 및 추가 여부를 확인한다. R은 명시적인 의미 모순에 추가 감점을 부여한다.

현재 가중치는 경험적으로 설정한 휴리스틱 설계값으로, 통계적으로 최적화되거나 독립적인 데이터에서 검증된 값은 아니다.

### 4.2 유사도 기반 대체 평가

Claim이 충분히 추출되지 않아 Claim 기반 계산이 불가능한 경우 다음 공식을 사용한다.

**M = 100 × S**

해당 결과는 `SIMILARITY_ONLY`로 구분한다.

이번 실험에서는 32개 문장 중 2개가 이 방식을 사용하였다.

다만 Claim 기반 평가와 유사도 기반 대체 평가는 계산 방식이 다르므로, 두 점수를 완전히 동일한 척도로 해석해서는 안 된다.

### 4.3 Meaning Score와 Verification Verdict의 차이

Meaning Score는 의미 보존 정도를 수치화한 결과이며, Verification Verdict는 최종 검증 판정이다.

Verification Verdict는 `PASS`, `REVIEW`, `FAIL`로 구분된다.

특히 Gemini 기반 의미 검증은 양태, 시제, 부정, 정보 추가 등의 의미 변화를 별도로 확인한다.

현재 Meaning Score 공식에는 Gemini의 의미 오류 탐지 결과가 직접적인 감점 요소로 포함되지 않는다. 따라서 Meaning Score가 높더라도 Verification Verdict에서 문제가 발견될 수 있다.

이 때문에 최종 결과는 Meaning Score와 Verification Verdict를 함께 해석해야 한다.

## 5. 결과 해석

이번 실험에서는 C 조건의 전체 파이프라인이 32개 평가 문장을 모두 처리했으며, 실행 오류는 발생하지 않았다.

또한 자동 재번역이 필요한 사례에서 실제로 재번역 및 재검증 과정이 실행되었고, 일부 사례에서는 최종 검증 판정이 개선되었다.

따라서 이번 실험은 다음 사항을 확인했다는 의의가 있다.

1. Style Profile과 RAG를 활용한 개인화 번역 파이프라인이 실행되었다.
2. 번역 결과에 대한 의미 검증 및 Meaning Score 계산이 정상적으로 수행되었다.
3. 검증 결과에 따른 자동 재번역 기능이 실제 실행 환경에서 작동했다.
4. 문장별 결과와 전체 통계가 CSV 파일로 저장되었다.

다만 최종 PASS 비율 96.88%는 시스템 내부 검증 판정의 비율이며, 사람이 직접 평가한 번역 정확도 96.88%를 의미하지 않는다.

## 6. 실험의 한계

### 6.1 독립적인 평가셋의 부재

이번 실험에 사용한 32개 한국어 원문은 Meaning Score 개발 과정에서도 활용된 데이터이다.

따라서 본 결과는 독립적인 홀드아웃 테스트셋에서 측정한 일반화 성능이 아니라 기존 평가 문장을 활용한 C 조건 실행 결과로 해석해야 한다.

### 6.2 제한된 표본 크기

평가 문장이 32개로 제한되어 있어 다양한 문장 구조와 의미 오류 유형을 충분히 대표한다고 보기 어렵다.

### 6.3 Meaning Score의 판별력 한계

Meaning Score는 일부 양태, 시제, 부정 등의 의미 오류를 충분히 반영하지 못할 수 있다.

특히 Claim 기반 NLI가 특정 의미 변화를 탐지하지 못하면 실제 의미 오류가 존재하더라도 높은 점수가 산출될 가능성이 있다.

### 6.4 평가 방식 간 척도 차이

`CLAIM_BASED`와 `SIMILARITY_ONLY`는 서로 다른 계산 방식을 사용한다.

따라서 두 방식의 점수를 직접 비교할 때 주의가 필요하다.

### 6.5 문체 개인화 효과의 미검증

이번 실험은 의미 보존과 파이프라인 실행 결과를 중심으로 수행되었다.

따라서 LinguaMe의 번역이 일반 번역보다 실제 사용자의 영어 문체를 더 정확하게 재현하는지는 별도의 평가가 필요하다.

### 6.6 A/B/C 조건 간 비교 미실시

현재 C 조건의 실행 결과만 확보된 상태이므로 A/B 조건 대비 성능 향상 여부를 판단할 수 없다.
