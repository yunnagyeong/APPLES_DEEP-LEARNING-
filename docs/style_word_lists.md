# 스타일 지표 단어 리스트: 출처와 점검표 (투두 5번 "피처별 단어 리스트 출처 명시")

> 작성: B 세션(2026-10-23). 횟수는 raw 코퍼스 essay+report 67편에서 문자열 포함 횟수(`str.count`)로 센 값이라 형태소 분석 결과와 다를 수 있음(예: "수 있다"는 "수도 있다"와 별개로 셈, "즉"은 다른 단어 안의 글자도 셈). **점검 칸은 팀원이 채웁니다(AI가 아니라 사람이 판단).**

## 출처 요약

- `LOGICAL_CONNECTIVES`, `HEDGING_EXPRESSIONS`, `EXAMPLE_MARKERS`, `CONCLUSION_MARKERS`: `docs/style_profile_spec.md`(1주차 초안, 팀원① 작성)의 사전을 `src/style_features.py`(2026-09-07 최초 커밋)에 옮긴 것. 코드 주석은 "팀 회의에서 확정된 표현으로 계속 보강해나가는 리스트"라고 되어 있으나, **어느 회의에서 확정했는지, 코퍼스를 보고 정한 것인지는 기록이 없음**(출처 미문서화 상태가 5번 문제의 원인).
- `FUNCTION_WORD_GROUPS`(24번): D-003의 1차 묶음(대조·인과/결론·목적) 틀 + 같은 코퍼스에서 작성자 간 차이가 큰 형태소를 보고 채운 표현. **선택 편향 가능**(B-012 한계 1).
- 영어 지시문(`FUNCTION_WORD_INSTRUCTIONS`)의 한국어→영어 대응(그러나→however 등)은 근사 가정이며 검증되지 않음.

## 알려진 문제 (코드·코퍼스에서 확인한 것)

1. `수 있다`·`수도 있다`·`일 수 있다`는 완곡(헤징)이 아닌 가능·능력 의미("할 수 있다")도 셈. 위 횟수에서 `수 있다`가 압도적으로 많은 이유로 추정되지만 의미별로 나눠 센 것은 아님(검증 필요).
2. `따라서`가 `LOGICAL_CONNECTIVES`와 `CONCLUSION_MARKERS` 양쪽에 있음. 24번 `therefore` 그룹(따라서·그러므로)과도 겹침(지표가 서로 독립이 아님).
3. `그리고`는 단순 나열이라 논리 관계 명시와 거리가 있음. `즉`은 한 글자라 다른 단어 안에서도 걸릴 수 있음(형태소 기반이 아니라 문자열 매칭, `logical_connective_rate` 계산 방식 확인 필요).
4. 연결어미(-므로·-어서·-지만 등)는 `LOGICAL_CONNECTIVES`에 없고 24번 `causal`에만 있음. D-007 ④의 원문 대응 확인에서는 연결어미도 포함해야 함.
5. 헤징 리스트는 8개뿐이라 "~ㄹ지도 모른다", "~듯하다", "~로 보인다", "~라고 생각한다", "~편이다" 같은 흔한 표현이 빠져 있음. 22번 효과 확인에서 본 손실 사례("생각한다", "해 보인다")는 리스트에 없어도 번역 프롬프트의 공통 규칙으로 처리하고 있음(지표 값과 별개).

### `FUNCTION_WORD_GROUPS` (24번 기능어 선택, 형태소 매칭이라 위 표와 방식이 다름)

| 그룹 | 규칙 (형태, 품사) | 팀 점검 |
|---|---|---|
| however | 그러나(MAJ) | ☐ |
| but | 하지만(MAJ), 그렇지만(MAJ) | ☐ |
| whereas | 반면(NN) | ☐ |
| therefore | 따라서(MAJ), 그러므로(MAJ) | ☐ |
| causal | 므로(EC), 으므로(EC), 어서(EC), 아서(EC), 그래서(MAJ) | ☐ |
| purpose_formal | 고자(EC) | ☐ |

- 점검 방법(팀원 2명 권장, 독립): 각 그룹이 "같은 기능"인지, 영어 대응(however/but/whereas/therefore/since·because/in order to)이 자연스러운지, 코퍼스 밖에서 흔히 쓰는데 빠진 표현이 있는지.
- 제외한 항목과 이유: 와/과(병렬), 것 구문(명사화), 인용 -다고/-라고(영어에서 선택지가 없음), 시/NNB·재/XPN(강희 IT 보고서 주제 의존).
